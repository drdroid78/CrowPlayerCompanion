# CrowPlayer Companion 0.6.2 — избранное через аккаунт Яндекса

## Что добавлено

- Вход по OAuth Device Flow: CrowPlayer показывает код, пользователь открывает страницу Яндекса в браузере и подтверждает вход. Пароль вводится на странице Яндекса.
- Токен сохраняется в зашифрованном виде (AES-GCM); ключ создаётся в Android Keystore. Резервное копирование данных приложения отключено. Аккаунт можно отключить или сменить. Истечение срока/отзыв токена требует повторного входа.
- При подключённом аккаунте и активной медиасессии Яндекс Музыки сердечко управляет серверным списком «Мне нравится». Перед переключением читается актуальное состояние, после POST выполняется повторное чтение. Отправка запроса сама по себе не считается подтверждением.
- Состояние избранного читается при смене трека и обновляется с интервалом не чаще 30 секунд. Токен и содержимое OAuth-запросов не включаются в диагностику.
- Нажатие учитывает показанное состояние сердца. Если нужное состояние уже установлено в Яндексе, повторная команда не отправляется. Неизвестное состояние трактуется как запрос добавления, чтобы случайно не снять существующий лайк.
- Трек определяется по Media ID либо ссылке Яндекс Музыки и проверяется по названию, исполнителю и длительности. Если Media ID отсутствует, выполняется поиск с проверкой названия, исполнителя, альбома (если он известен) и длительности. При нескольких совпадениях пользователь выбирает запись; первый результат поиска автоматически не лайкается.
- Запрос привязан к медиасессии, треку и подключённому аккаунту. Смена трека/аккаунта или закрытие сервиса отменяют дальнейшие действия. Команда, которая могла уже дойти до сервера, автоматически не повторяется через другой способ.
- Без подключённого аккаунта остаётся управление опубликованными медиакомандами из 0.6.1. Перемотка, BLE-протокол и прошивка CrowPanel не изменены этой версией.

## Как проверить

1. Установить APK, включить доступ к уведомлениям и запустить музыку.
2. В CrowPlayer нажать «Войти в Яндекс», открыть страницу Яндекса, ввести показанный код и подтвердить вход. Использовать тот же аккаунт, что и в приложении Яндекс Музыки.
3. Вернуться в CrowPlayer, дождаться чтения избранного и проверить лайк → снять → лайк. Проверить результат непосредственно в «Мне нравится» Яндекс Музыки.
4. Если предложен выбор записей, выбрать нужную версию песни. Для неподтверждённых/локальных записей приложение может отказать в изменении.
5. Проверить смену трека во время запроса, отключение интернета и выход из аккаунта. Сердечко не должно выдавать неподтверждённый результат за успешный.

## Источники протокола

Независимая реализация на Kotlin по изученному протоколу проекта [MarshalX/yandex-music-api](https://github.com/MarshalX/yandex-music-api):

- [Лайки: add-multiple, remove и чтение library](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/likes.py).
- [OAuth Device Flow и публичные параметры клиента](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/device_auth.py).
- [Авторизация HTTP-запросов](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/utils/request_base.py).

Python-библиотека в APK не включается. Неофициальный API может меняться; OAuth и фактическое обновление избранного необходимо отдельно подтвердить на Huawei/HarmonyOS с пользовательским аккаунтом. Автоматические тесты используют имитированный сервер и не входят в реальные аккаунты.

## Проверки

```sh
gradle -p android :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Включены проверки OAuth-входа/отмены, формата запросов, идентификации трека, шифрованного хранения, подтверждения лайка/снятия, неоднозначного поиска, смены аккаунта/трека, запоздалых ответов, тайм-аута и неопределённого результата после сетевой ошибки. Проверки медиакоманд из 0.6.1 также сохранены.
