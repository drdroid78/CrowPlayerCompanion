# CrowPanel Škoda Edition — сенсорная прошивка

Целевая плата: Elecrow CrowPanel 1.28″, ESP32-S3R8, GC9A01 240×240, CST816D, энкодер, 5 адресных LED.

## Управление

- Горизонтальный свайп: часы → музыка → звук → источники → настройки.
- Вертикальный свайп: громкость HAM. На экране звука касание шкалы «САБ» переключает регулировку на сабвуфер; касание основной шкалы возвращает громкость.
- Энкодер: громкость; в настройках — выбор параметра, после нажатия — изменение значения.
- Кнопка: одиночное нажатие play/pause, двойное следующий трек, удержание 700 мс mute. В настройках удержание возвращает музыку.
- Музыка: касание сердечка, предыдущего/следующего трека и play/pause.
- Экран звука: касание MUTE.
- Источники: только реально объявленные усилителем входы. Подпись AUX не появляется, если его нет в SOURCE_CONFIG.
- Дежурный экран после 30 секунд без действий; отключение и задержка настраиваются.

Тема, расписание, яркость экрана/LED и задержка дежурного экрана сохраняются в NVS с отложенной записью. Восемь тем из набросков. Škoda Green выбран #4BA82E как цвет этого проекта, без утверждения о заводском коде.

День по умолчанию 07:00–22:00: экран 80%, LED 35%; ночь: экран 18%, LED 6%. Плавная регулировка экрана. До синхронизации времени экран 18%, LED 6%, часы `--:--`. Время сохраняет ход при потере USB до перезагрузки; аппаратных автономных часов нет.

## Аппаратные соединения

Распиновка платы сверена с официальными примерами, см. ELECROW_BOARD_REFERENCE_RU.md.

HAM: 115200 8N1, **инвертированы RX и TX**, RX GPIO44, TX GPIO43, общий GND. Логические уровни HAM **1,8 В**, ESP32-S3 **3,3 В**: нужен внешний двунаправленный по направлениям RX/TX преобразователь уровней; программная инверсия не преобразует напряжение. Не добавлять вторую инверсию в преобразователе. Выводы 43/44 должны быть выведены на используемый разъём/проводку.

USB: native USB D−19/D+20, режим USB-OTG/TinyUSB, отдельный CDC-интерфейс. UART0/debug на 43/44 не используется, чтобы не мешать HAM. BLE полностью исключён из новой прошивки. Wi-Fi нужен исключительно для OTA и отключён при пустых данных в crowplayer_secrets.h.

## Протокол HAM

Основан на рабочем описании, присланном пользователем; совместимость с HAM 4.8 и инверсия/1,8 В подтверждены пользователем. Это не официальная спецификация производителя.

`AA 77 LEN GROUP COMMAND TYPE DATA... CHECKSUM`; размер `LEN+4`, сумма начиная с LEN включительно равна нулю modulo 256. GET 66, VALUE_REPORT DD, SET BB, ACK EE с DATA[0]=0A. Пакеты с ошибочной длиной/checksum игнорируются; незавершённый пакет сбрасывается после 30 мс.

Используются команды группы 01: 00 список источников, 01 источник, 02 громкость, 03 сабвуфер, 04 mute. Источники: внутренний ID и wire-код `51+ID`. Громкость: отчёт `int8(raw)+60`, запись `42-volume`; сабвуфер: отчёт `int8(raw)`, запись `-value`. Единицу сабвуфера «дБ» не утверждаем. Диапазоны записи намеренно ограничены: основная громкость 0…60, сабвуфер −60…0; предельные аппаратные диапазоны требуют отдельного подтверждения.

На старте и далее опрашиваются только параметры интерфейса; неизвестные configuration/ACC/MCU команды не используются. На запись ожидаются ACK и/или фактический VALUE_REPORT. Сам ACK не меняет отображаемое значение. Повтор SET автоматически не отправляется. Отсутствие актуальных отчётов 3,5 секунды показывает отсутствие связи. DSP-пресеты не реализованы: в переданной карте нет подтверждённой команды выбора пресета.

## USB CDC v1

UTF-8 JSON, одна строка на сообщение, LF, максимум 2047 байт. Переполненная строка отбрасывается целиком до LF. Скорость при открытии CDC 115200 (USB не физический UART). Android — USB host/OTG. Панель — USB device. Никакого сетевого канала к планшету.

Компаньон → панель, `state` не реже одного раза в секунду:

```json
{"v":1,"type":"state","title":"Группа крови","artist":"Кино","state":"playing","positionMs":87000,"durationMs":214000,"liked":true,"likeAvailable":true,"epochMs":1794515760000,"utcOffsetMinutes":180}
```

`liked:null` означает неизвестное состояние. Если лайк недоступен/неизвестен, панель не отправляет переключение вслепую. Допустим `{"v":1,"type":"heartbeat"}` между state. Через 5 секунд без валидного state/heartbeat USB считается недоступным.

Панель → компаньон:

```json
{"v":1,"type":"command","id":1,"action":"like","liked":false,"title":"Группа крови","artist":"Кино"}
```

`action`: `play_pause`, `previous`, `next`, `like`. Компаньон должен привязать лайк к текущему треку, проверить title/artist и вернуть фактическое состояние:

```json
{"v":1,"type":"result","id":1,"ok":true,"liked":false}
```

При ошибке `ok:false`. Сердечко не меняет состояние от самого нажатия. Таймаут команды 3 секунды; результат с чужим/устаревшим id игнорируется. Токены Яндекс Музыки не передаются панели.

**Android-компаньон 0.6.3 использует USB host/CDC ACM** и передаёт JSON-lines версии 1 по физическому OTG-кабелю. На первом подключении Android запрашивает USB-доступ. Метаданные отправляются каждую секунду, панельные команды play/pause, next/previous и like проходят обратно с подтверждением. BLE для этой версии прошивки не используется. Обложки по USB пока не передаются; панель показывает музыкальную заглушку.

## Воспроизводимая сборка и просмотр

GitHub Actions `.github/workflows/build-panel.yml`: тесты C++ с ASan/UBSan, генерация кириллических шрифтов, отрисовка всех экранов всех тем, Arduino CLI compile для ESP32-S3R8. Версии: Arduino-ESP32 3.3.8, LVGL 9.1.0, LovyanGFX 1.2.26, NeoPixel 1.15.1, ArduinoJson 6.21.5, lv_font_conv 1.5.3. Шрифты генерируются из DejaVu Sans на Ubuntu.

`firmware/preview/main.cpp` компилирует **тот же panel_ui.cpp**, что и устройство. PNG — снимки LVGL 240×240 с демонстрационными медиаданными и состоянием HAM, не фотографии подключённой панели. Демоданные не входят в рабочую прошивку.

Артефакт сборки содержит бинарники и превью. Для USB-прошивки предпочтителен merged binary по адресу 0x0, если он создан CLI; отдельный `.ino.bin` предназначен для app-раздела/OTA, его нельзя записывать по 0x0. Адреса отдельных образов брать из build/panel/flash_args или вывода Arduino CLI. Загрузка на физическую панель в этой задаче не выполняется.

Аппаратная проверка ещё нужна: направление/число шагов энкодера, ориентация сенсора, порядок RGB/LED, фактические UART-подтверждения, USB host Android, яркость и читаемость. Успешная сборка и снимки интерфейса не заменяют её.
