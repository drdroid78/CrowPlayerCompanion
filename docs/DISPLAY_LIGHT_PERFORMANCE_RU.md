# CrowPanel: Godwit Light и отрисовка
Дата: 19 ноября 2026. Эти изменения требуют проверки на физической панели.

Название снова CrowPanel. Заставка восстановлена с подписью © 2026 DrDroid78.
Тема Godwit Light — девятый пункт; прежние индексы 0..7 и сохранённые настройки совместимы. Между темами можно переключаться энкодером/свайпом на экране «Тема».
Светлая палитра: #FFFFFF, #1A1A1A, #4A4A4A, #3D7B31, #CACACA.
Inter Regular / SemiBold, с DejaVu для символов музыки; все шрифты конвертируются в сборке в LVGL 4bpp. Исходные начертания и лицензия Inter сохранены.
Шкала громкости светлой темы: 270°, радиус внешнего края 114, ширина 2..14 пикселей.

## Рендер
UI-объекты сохраняются между кадрами. Структура пересоздаётся при смене экрана, темы или входе/выходе оверлея; если изменяется структура условных элементов, перестраивается только её хвост.
Текст не назначается заново, когда он не изменился. Содержимое обложки инвалидируется по revision.
Оверлей громкости допускает обновление каждые 33 мс вместо 180 мс. Это предел планировщика, НЕ измеренный FPS.
Два статических выровненных буфера 240*40*2 байта во внутренней памяти. Используются pushImageDMA, waitDMA, startWrite/endWrite. LVGL получает flush_ready только после завершения передачи. Размещение буферов проверяется по ELF map и runtime esp_ptr_dma_capable.
Для аппаратного сравнения можно собрать с -DCROWPANEL_SYNC_DISPLAY=1: один буфер и синхронная передача при том же UI. Это сравнивает транспорт, не возвращает старый renderer.
Для проверки старого renderer нужен откат к коммиту e09e15eec1d043d36aad8690dff311c557b9fa98 (код прошивки там соответствует db5a637).

## Измерения
Первые 120 секунд после старта USB CDC публикует perf JSON: renderCount, renderUs (сумма времени cp::render), renderMaxUs, flushUs (время от запуска передачи до фиксации её завершения), flushMaxUs, pixels, uiAllocations, sync.
Разности renderUs/renderCount дают среднюю стоимость построения объектов, а не время полного кадра. flushUs включает задержку обнаружения завершения и не является точным временем на проводе. Учитывать LVGL software rasterization отдельно. Перед сравнением использовать одинаковый экран/трек/темп вращения.
Ожидается снижение аллокаций и лишней работы; реальный FPS, стабильность USB/HAM и отсутствие артефактов подтверждаются только на устройстве.

## Автопроверки

panel_preview: повторный кадр не создаёт объектов, retained и fresh render совпадают.
panel_reference + panel-check-preview.py: 48 кадров прежних восьми тем пиксельно совпадают с исходным кодом.
panel-check-map.py: обе DMA-области выровнены и в SRAM.
